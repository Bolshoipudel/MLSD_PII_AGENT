# Данные проекта

Тексты и исходные файлы хранятся только локально. В Git входят эта инструкция и
`data/splits/*.json`: ID, хеши исходных текстов и группы разбиения, без самих текстов.
Сводки, графики, исправления выравнивания и манифесты находятся в `eda/`.

## Воспроизведение

Из корня репозитория; Python 3.12, зависимости зафиксированы в `uv.lock`:

```bash
uv sync --locked --extra eda

# Разработка: эти команды не скачивают и не читают PII-Bench.
uv run --locked --extra eda python -m scripts.data.download
uv run --locked --extra eda python -m scripts.data.prepare
uv run --locked --extra eda python -m scripts.data.verify

# Отдельная подготовка оценки, выполняется вне среды оптимизирующего агента.
uv run --locked --extra eda python -m scripts.data.download --scope evaluation
uv run --locked --extra eda python -m scripts.data.prepare --scope evaluation
uv run --locked --extra eda python -m scripts.data.verify --scope evaluation

# Аудит пересечений выполняет исследователь; агенту доступен только его итог.
uv run --locked --extra eda python -m scripts.data.audit
uv run --locked --extra eda python -m scripts.data.eda

# Выполнить ноутбук и сохранить результаты в нём.
uv run --locked --extra eda python -m scripts.data.run_notebook
```

Для сервера без домашнего каталога можно указать `UV_CACHE_DIR` и `MPLCONFIGDIR`
в доступных для записи временных каталогах. Для повторной идентичной подготовки
ничего удалять не нужно. При намеренном изменении алгоритма или окружения команда
`prepare` потребует `--force` либо новый `--output-dir`; после этого пересматриваются
манифесты и все производные результаты. В уже начатом эксперименте менять сплиты нельзя.

Загрузчик сверяет SHA-256 до использования кеша и до замены файла.
Нормализатор повторно сверяет хеши; исходные тексты и исходная разметка сохраняются.
`start` включён, `end` исключён; единицы измерения — Unicode code points в Python,
а не UTF-8-байты или UTF-16 позиции JavaScript.

```text
data/raw/pii_benchmarks/redmadrobot/test.csv
data/raw/pii_benchmarks/hivetrace/{domain,entity}.parquet
data/processed/development/{opt_train,golden}.jsonl
data/processed/evaluation/{domain,entity}.jsonl
data/splits/{development,evaluation}.json
```

В старом исследовательском репозитории был общий split 70/15/15. Он не используется
в текущем протоколе. Модели на нём не обучались и не настраивались, по сообщению автора.
Новый development split содержит **1 978 / 863** текста (около 70/30), seed 42.
Точные тексты, одинаковые шаблоны после маскирования сущностей и близкие шаблоны
(char 5-gram Jaccard ≥ 0.85, длина шаблона ≥ 30 для нечёткого сравнения) объединяются
в компоненты связности; компонент целиком попадает в одну часть. После жадного
назначения выполняется балансировка целыми группами по размеру, наличию сущностей
и типам. Точное соотношение размеров не навязывается ценой разрыва групп.
Это эвристика против утечек; семантическая независимость не доказана.

## Ограничения разметки

Переименованы только `PHONE_NUMBER → PHONE`, `BANK_CARD_NUMBER → CREDIT_CARD`,
`PASSPORT_NUMBER → PASSPORT`. `native_type`, `native_label_scope`, исходная разметка,
источник и его ревизия остаются в записи. `label_scope` — область исходной разметки,
а не список типов, действительно присутствующих в конкретном тексте.

Имена и компоненты адресов не склеиваются автоматически. У паспортов совпадает
название класса, но различаются границы: серия и номер могут быть разными спанами.
Тип вне `label_scope` считается неизвестным, а не отрицательным примером.
Поэтому 28 меток общего инвентаря не означают 28 полностью размеченных классов
в каждом источнике и не расширяют 13 целевых типов продукта.

Текущий `golden` пригоден для предварительной диагностики в родной схеме redmadrobot.
Он ещё не покрывает все 13 целевых типов и не допускает полноценную проверку БТ-4.
План пополнения и бюджет разметки — в [отчёте EDA](../eda/report.md).
